# Real Taste of Africa — Houston-first

Modern, UX-first web app for an **African restaurant directory**. Starting with **Houston, Texas + neighboring cities**, built to expand nationwide over time.

## Tech

- Next.js (App Router) + TypeScript
- Tailwind CSS
- ESLint (Next.js config)

## Run locally

```bash
cd realtasteofafrica
npm install
npm run import:restaurants
npm run dev
```

Then open `http://localhost:3000`.

## Environment variables

Copy `.env.example` to `.env.local` and fill in values. For the **Claim listing** flow (PayPal):

- `NEXT_PUBLIC_PAYPAL_CLIENT_ID` — from [PayPal Developer Dashboard](https://developer.paypal.com/dashboard/); used by the browser SDK.
- `PAYPAL_CLIENT_SECRET` — same app; used only on the server to create orders. Never commit this.
- `PAYPAL_SANDBOX=true` — use sandbox for testing; omit or set to `false` for live payments.

## Project structure

- `src/app/`: routes (Home, Browse, Area pages, Restaurant detail, Submit, Contact)
- `src/components/`: UI building blocks + header/footer
- `src/lib/`: areas + directory logic

## Real data (no paid APIs)

We seed real restaurant listings from a CSV (Google Sheets friendly):

1. Update `data/restaurants.csv` (you can export from Google Sheets as CSV).
2. Generate app data:

```bash
npm run import:restaurants
```

This generates `src/data/restaurants.generated.ts`, which the app uses at runtime.

## Optional: bootstrap listings from OpenStreetMap (free)

You can pull an initial set of African-cuisine restaurants from OSM (Overpass API) and export to CSV:

```bash
npm run fetch:restaurants:osm
```

This writes `data/restaurants.osm.csv`. Review/clean it (OSM data can be incomplete), then copy the rows you want into `data/restaurants.csv` and run:

```bash
npm run import:restaurants
```

To use a custom bounding box:

```bash
npm run fetch:restaurants:osm -- --bbox "29.35,-95.95,30.25,-94.95"
```

## Data maintenance scripts

Run these from the project root (`realtasteofafrica/`).

| Script | Purpose |
|--------|--------|
| `node scripts/audit-batch-html.mjs` | Generates `data/audit-batch.html`. Open in browser, run `auditBatch(0, 10)` in the console to open 10 tabs at a time for manual audit. |
| `node scripts/find-duplicates.mjs` | Flags same address, same phone, and names &gt;70% similar so you can merge or remove duplicates. |
| `node scripts/standardize-csv.mjs` | Formats phones as (XXX) XXX-XXXX, title-cases cities, ensures `category` and `internal_verified` columns. |
| `node scripts/ghost-locations.mjs` | Lists addresses with 5+ restaurants (possible ghost kitchen hubs) for manual review. |
| `node scripts/set-internal-verified.mjs slug1 slug2` | Sets `internal_verified=true` for given slugs (or `--file slugs.txt`). Then run `npm run import:restaurants`. |
| `node scripts/generate-audit-list.mjs` | Builds `data/audit_list.json` (name, city, type, status, verified, region) for manual audit tracking. |
| `node scripts/data-integrity.mjs` | Report: duplicates (same name + city), name standardization (LLC/Inc), type/region. Use `--fix` to apply. |
| `node scripts/audit-directory.mjs` | Red-flag keywords (closed, inactive, moved, etc.) in names; duplicates (same name + city). Use `--csv` to also check writeUp. |

**Audit tracking:** Add an `internal_verified` column to your CSV (true/false). As you verify each listing (e.g. via the audit batch), set it to `true`. The type and import support this field; it is for internal use only (not shown on the site).

**Finding new listings:** See `docs/search-operators.md` for Google search queries (e.g. `site:yelp.com "African" "Austin, TX"`) to discover restaurants without an API.

**Audit checklist:** Use `data/audit_list.json` (generated by `node scripts/generate-audit-list.mjs`) to track manual verification. See `docs/audit-verification.md` for known potential duplicates and manual verification steps (Facebook, Market + Kitchen calls, ghost kitchen addresses).

**Data pruning:** See `docs/data-pruning.md`. Move closed listings to `data/deleted_restaurants.json` with `node scripts/move-to-deleted.mjs <slug> [reason]`. Normalize ghost kitchen names (e.g. "Aria Suya (Wilcrest Ghost)" → "Aria Suya", category Ghost Kitchen) with `node scripts/normalize-ghost-names.mjs [--fix]`.
